# Обновление протокола на сервере без потери пользователей

## Проблема в оригинальном Amnezia

Всё состояние протокола живёт внутри Docker-контейнера в `/opt/amnezia/<протокол>/`:
ключи сервера, `awg0.conf` с секциями `[Peer]`, `server.json` с клиентами XRay, `clientsTable`.

Любая «переустановка» (обновление версии, смена порта, H1–H4/S1–S4 у AmneziaWG) удаляла контейнер
и заново запускала `configure_container.sh`, который генерирует **новые ключи** и пустой конфиг.
Смена сайта XRay делала то же самое даже без переустановки. Итог — все выданные конфиги переставали работать.

## Как работает теперь

### Кнопка «Update on server» (настройки протокола)

Транзакционное обновление (`client/server_scripts/upgrade_container.sh`), выполняется на сервере целиком
под `nohup`, поэтому обрыв SSH не оставляет сервер в промежуточном состоянии:

1. **snapshot** — `/opt/amnezia` работающего контейнера копируется на хост в
   `/opt/amnezia/.state/<контейнер>/<дата>` (хранятся 5 последних снимков);
2. **build** — новый образ собирается под тегом `:next`, старый контейнер продолжает обслуживать клиентов;
   ошибка сборки (например, лимит Docker Hub) → ничего не меняется;
3. **swap** — старый контейнер останавливается и переименовывается в `<контейнер>-prev`;
4. **restore** — запускается новый контейнер, в него возвращается снимок и накладываются изменённые файлы (overlay);
5. **verify** — health check протокола (`awg show awg0`, `wg show wg0`, `pgrep -x xray`);
6. **commit / rollback** — при успехе `-prev` удаляется, при любой ошибке автоматически возвращается старый контейнер.

Простой — несколько секунд. Ключи не меняются, поэтому клиенты переподключаются сами.

### Изменение настроек сервера

`InstallController::updateServerConfig` больше не переустанавливает протокол с нуля, если состояние можно сохранить
(`client/core/utils/selfhosted/serverStatePatcher.cpp`, для XRay — `XrayConfigurator::buildPreservedServerConfig`):

| Изменение | Раньше | Теперь |
|---|---|---|
| AWG: порт, Jc/Jmin/Jmax, S1–S4, H1–H4 | новые ключи, все пиры удалены | патчится только `[Interface]`, ключи и `[Peer]` сохраняются, контейнер пересоздаётся транзакционно |
| **AWG 2.0 → 3.1** (HeaderProtectionKey, ContentPadding, тайминги) | переустановка, все пользователи удалены | новые ключи AWG 3.1 дописываются в `[Interface]`, пользователи и их адреса сохраняются |
| WireGuard: порт | новые ключи | то же, что для AWG |
| XRay: порт, транспорт, flow и др. | новые UUID/ключи | `server.json` собирается заново, но со старыми ключами Reality и всеми клиентами |
| XRay: сайт (SNI) | новые UUID/ключи | новый сайт добавляется в `serverNames`, **старый остаётся** — уже выданные конфиги продолжают работать |
| Подсеть AWG/WireGuard | переустановка | переустановка (адреса пиров привязаны к подсети) |

Изменения H1–H4/S1–S2 и порта по-прежнему требуют раздать пользователям обновлённые конфиги —
но пользователи, их ключи и адреса остаются на сервере.

### Мелкие исправления серверных скриптов

- `start.sh` AWG/WireGuard/XRay: правила iptables добавляются идемпотентно, рестарты контейнера больше не плодят дубликаты;
- XRay: firewall внутри контейнера пропускал только 80/443 — нестандартный порт XRay молча блокировался;
- XRay: супервизор перезапускает упавший `xray`; добавление/удаление пользователя перезагружает только `xray`
  (`pkill`), а не весь контейнер, остальные клиенты не отключаются (для старых серверов — прежний `docker restart`);
- удалена дублирующаяся проверка занятости порта при установке.
